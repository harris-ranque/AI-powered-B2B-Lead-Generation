I'll create a comprehensive artifact with your final architecture and provide recommendations for your repository structure and migration requirements.## Repository Structure Recommendation

### **Recommended: Two Repository Approach**

```
lead-eternity/
├── lead-eternity-app/          # Repository 1
│   ├── apps/
│   │   ├── web/               # React frontend
│   │   └── crewai-worker/     # Python CrewAI
│   ├── packages/
│   │   └── shared-types/      # Shared TypeScript types
│   ├── package.json           # Root package.json
│   ├── railway.json          # Multi-service config
│   └── README.md
│
└── lead-eternity-convex/      # Repository 2
    ├── convex/
    │   ├── schema.ts
    │   ├── auth.config.ts
    │   └── functions/
    ├── .env.local
    └── README.md
```

**Why Two Repos:**
1. **Convex has its own deployment flow** (npx convex deploy)
2. **Railway can deploy monorepo** with multiple services
3. **Cleaner CI/CD pipelines**
4. **Type sharing via npm package**

### **Alternative: Full Monorepo**

If you prefer everything together:

```
lead-eternity-monorepo/
├── apps/
│   ├── web/                # React frontend
│   ├── convex/            # Convex backend
│   └── crewai-worker/     # Python worker
├── packages/
│   └── config/            # Shared configs
├── railway.json
└── turbo.json            # Turborepo config
```

### **2. Data Migration**
```typescript
// Migration script example
export const migrateN8NData = internalMutation({
  handler: async (ctx) => {
    // 1. Export from N8N database
    // 2. Transform data structure
    // 3. Import to Convex
    
    const n8nData = await fetchN8NData();
    
    for (const record of n8nData) {
      await ctx.db.insert("leads", {
        // Map N8N fields to Convex schema
        businessName: record.company_name,
        email: record.primary_email,
        // ... etc
      });
    }
  }
});
```
